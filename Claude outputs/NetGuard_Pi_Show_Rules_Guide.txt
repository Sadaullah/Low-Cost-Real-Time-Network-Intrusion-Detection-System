=====================================================================
  NetGuard Pi - How to SHOW YOUR OWN RULES in the demo
  (if the supervisor asks: "show me your rules")
  Run these on the PI (PuTTY or the Pi terminal).
=====================================================================

1) SHOW ALL YOUR RULES
---------------------------------------------------------------------
Your 13 FYP-IDS rules (SIDs 1000001-1000013):
    cat /etc/suricata/rules/local.rules

Your 5 team rules (SIDs 9000001-9000005):
    cat /var/lib/suricata/rules/local.rules

Show BOTH files together, with line numbers:
    cat -n /etc/suricata/rules/local.rules /var/lib/suricata/rules/local.rules


2) SHOW ONE SPECIFIC RULE (if he points at one)
---------------------------------------------------------------------
Example - the SSH brute-force rule:
    grep "sid:1000006;" /etc/suricata/rules/*.rules /var/lib/suricata/rules/*.rules

(change 1000006 to any SID he asks about)


3) PROVE THE RULES ACTUALLY LOAD (expect: 18 rules, 0 failed)
---------------------------------------------------------------------
    sudo suricata -T -c /etc/suricata/suricata.yaml -v 2>&1 | grep "rules successfully"

This prints: "18 rules successfully loaded, 0 rules failed"
It proves the rules on screen are the ones really running.


=====================================================================
  HOW TO READ A RULE OUT LOUD (example: SSH brute force)
=====================================================================

alert tcp any any -> $HOME_NET 22 (msg:"FYP-IDS BRUTEFORCE Possible SSH
brute force"; flow:to_server,established; flags:S,12;
threshold:type both, track by_src, count 10, seconds 60;
classtype:attempted-admin; sid:1000006; rev:1;)

  alert ........................ raise an alert
  tcp any any -> $HOME_NET 22 ... TCP traffic from anyone, to our
                                  network on port 22 (SSH)
  msg .......................... the text shown in the alert
  threshold count 10, seconds 60 fire only after 10 connections in
                                  60 s (that is what makes it a brute
                                  force, not one normal login)
  track by_src ................. count per source IP (per attacker)
  sid:1000006 .................. the rule's ID number
  rev:1 ........................ the rule version
